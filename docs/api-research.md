# 분당 버스 MVP: 공개 API 검증 기록

확인일: 2026-09-11. 공식 명세를 조사한 결과이며, 인증키로 실제 운행 응답을 수집한 실험 결과는 아직 없다.

2026-10-12 재확인: 공식 위치 v2와 형상 v2 매뉴얼을 다시 확인했다. 위치 명세에 차량 GPS 좌표·측정시각은 여전히 열거되어 있지 않다. 실제 인증 응답과 갱신 간격은 미측정 상태다.

## 2026-10-16 첫 실제 관측

두 API의 인증과 조회가 성공했다. 공식 검색 결과에서 720-2번의 `routeId=234000026`, 경기고속차고지–백현마을8단지, 운행지역 성남·수원·용인·화성을 확인했다. 공식 정류소 203개, 형상점 1,743개가 유효했고 서현역·정자·백현 일대 경유를 확인했다. 정류소를 순번대로 형상에 투영했을 때 최대 매칭 거리는 21.7m였으며 200m 제외 기준을 넘는 정류소는 없었다. 이 수치는 버스 GPS 정확도가 아니다.

한 노선의 위치상태를 5초 간격·최대 24회·약 2분 동안 조회했다. 오류 0회, 상태 변화 73건, 차량별 변경 간격 표본 50개를 얻었다. 관측 중앙값은 25.0초, p90은 50.1초, p95는 75.2초였다. 차량별 연속 비교 중 동일 상태 비율은 88.1%였고 응답 소요시간 중앙값은 87ms였다. 이 결과는 한 시간대의 짧은 관측이며, 정차·짧은 관측창·폴링 사이 누락 등의 편향이 있다. 원천 API 또는 GPS의 갱신 주기로 해석하지 않는다.

실제 위치 응답에서 확인한 필드는 `crowded`, `lowPlate`, `plateNo`, `remainSeatCnt`, `routeId`, `routeTypeCd`, `stateCd`, `stationId`, `stationSeq`, `taglessCd`, `vehId`다. 차량 GPS 좌표와 차량별 측정시각은 실제 응답에도 없었다. 원본 차량번호 대신 실험별 가명을 기록했다. 원자료와 통계는 `measurements/2026-10-16T05-54-18-038Z/`에 저장했다.

첫 로컬 `/api/live` 확인에서는 차량 26대가 모두 공식 정류소와 매칭됐고, 그중 정자·서현·백현 구간의 정류소 순번 89~117에 4대가 있었다. 이는 해당 조회 시점의 수치다.

공개 공공데이터포털은 두 서비스 모두 개발계정 신청 가능 트래픽을 1,000으로 안내하며 오류 22는 일일 호출 허용량 초과로 설명한다. 일단 1,000회/일을 기준으로 보수적으로 계획하되, 사용자별 승인 한도·잔여량은 확인되지 않았다. 두 서비스의 한도를 더해 총량으로 간주하지 않는다. [위치 서비스](https://www.data.go.kr/data/15080648/openapi.do), [노선 서비스](https://www.data.go.kr/data/15080662/openapi.do)

## 확인된 핵심 제약

**GBIS 공개 위치 API v2에는 차량의 위도·경도와 차량별 GPS 측정시각이 명세되어 있지 않다.** 차량 식별자, 정류소 순번과 운행 상태를 제공한다. 공통 `queryTime`은 요청 시각으로 설명되므로 차량의 측정시각으로 사용하면 안 된다. 현재 공개 명세에서 고정된 원천 수집 간격도 확인하지 못했다. 따라서 이 프로젝트의 위치는 정류소와 노선 형상을 결합한 추정치이다. [GBIS 위치 API 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusLocation)

공식 BIT 화면은 10초마다 화면 정보를 갱신한다고 안내한다. 이 숫자는 공개 API 데이터 또는 차량 GPS의 생성 주기를 보장하지 않는다. [경기버스정보 BIT](https://www.gbis.go.kr/mybit)

## 요청 경로와 제공 필드

기준 주소는 `https://apis.data.go.kr/6410000/`이다. 아래 서비스는 `serviceKey`와 `format=json`을 사용한다. 위치·정류소·형상 요청에는 `routeId`가 필요하며, 노선 검색은 `keyword`를 사용한다.

| 기능 | 기준 주소 뒤 경로 | MVP에서 쓸 항목 |
| --- | --- | --- |
| 위치 | `buslocationservice/v2/getBusLocationListv2` | `vehId`, `plateNo`, `routeId`, `stationId`, `stationSeq`, `stateCd` |
| 노선 찾기 | `busrouteservice/v2/getBusRouteListv2` | `routeId`, `routeName`, `regionName`, 기·종점, 노선 유형 |
| 경유 정류소 | `busrouteservice/v2/getBusRouteStationListv2` | `stationId`, `stationName`, `stationSeq`, `x`, `y`, `turnSeq`, `turnYn` |
| 노선 형상 | `busrouteservice/v2/getBusRouteLineListv2` | `lineSeq`, `x`, `y` |

위치 응답의 추가 항목은 `routeTypeCd`, `crowded`, `remainSeatCnt`, `lowPlate`, `taglessCd`이다. `stateCd`는 0=교차로 통과, 1=정류소 도착, 2=출발이다. 빈자리·혼잡도는 모든 노선에서 제공되는 값이 아니므로 누락을 0으로 바꾸지 않는다. `remainSeatCnt=-1`도 빈자리가 0개라는 뜻이 아니다. [위치 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusLocation)

노선번호가 같은 다른 지역 노선을 피하려면 검색 결과의 운행지역·기종점과 실제 경유 정류소를 확인한다. `720-2`, `33`, `17`은 기존 대화의 **검색 후보**이며, 현재 경로·노선 ID가 확정된 목록은 아니다. 노선 번호를 식별자로 저장하지 않는다. [노선 검색 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRoute)

정류소에는 번호(`mobileNo`), 지역과 관할기관, 중앙차로 여부도 있다. 왕복·회차 노선을 처리할 때 정류소 ID만으로 매칭하지 말고 `stationSeq`를 함께 사용한다. [경유 정류소 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteStation)

형상 좌표는 `lineSeq` 순서로 정렬한다. 정류소 사이를 직선으로 연결한 선을 실제 도로 형상이라고 표시하지 않는다. 별도 기반정보 다운로드 서비스에는 노선·정류소·차량·노선-정류소·형상 파일과 버전 정보가 있어, 추후 정적 데이터 캐시를 관리하는 데 쓸 수 있다. [형상 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteLine), [기반정보 명세](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBaseInfo)

## 인증과 호출 예산

인증키는 공공데이터포털에서 발급받는다. 실제로 사용할 위치·노선 등 서비스의 활용 승인이 있는지 확인한다. 서버 환경변수로 보관하고 브라우저 번들·공개 저장소·로그에 넣지 않는다. 공식 위치 샘플은 HTTPS를 사용한다. [공식 키 발급 안내](https://gbis.go.kr/gbis2014/publicService.action?cmd=publickKey)

이번 조사에서는 **이 서비스의 최신 계정별 일일 허용량을 공식 원문으로 확정하지 못했다.** 다른 데이터셋의 1,000회 또는 10,000회 한도를 이 서비스에 적용하지 않는다. 활용 신청 화면에 실제로 표시된 승인량을 수집기 설정에 넣는다.

호출량 계획식은 `노선 수 × 관측 초 / 조회 간격 초`이다. 예를 들어 한 노선을 2초 간격으로 10분 관측하면 약 300회, 세 노선을 15초 간격으로 12시간 운영하면 약 8,640회다. 초기 호출·재시도·노선/정류소 요청분을 추가한다. 여러 사용자가 접속해도 서버가 한 번 조회한 결과를 공유한다.

## 키 등록 후 수행할 실험

1. 후보 노선을 검색하고 분당을 지나는 실제 `routeId` 한 개를 확정한다. 형상·정류소를 한 번 받아 저장한다.
2. 승인된 예산 안에서 2초 또는 더 긴 간격으로 우선 10분 관측한다. 요청 시작·완료 시각, 응답 코드, `queryTime`, 응답 필드 집합을 기록한다.
3. 차량별 `(stationId, stationSeq, stateCd)` 변경 간격과 전체 payload 변경 간격을 따로 집계한다. 첫 등장·재등장은 변경 주기 표본에서 제외한다. 0개 차량 응답과 통신 실패도 구분한다.
4. p50·p90·p95, 동일값 응답 비율, 오류율, 응답 지연을 표시한다. 결과 이름은 **관측된 위치상태 변경 간격**으로 한다. 고정된 GPS 갱신 주기 또는 지연의 실측값이라고 부르지 않는다.
5. 시간대를 바꿔 반복한다. 정차 중 값이 같을 수 있고 조회 사이에 여러 변경이 생길 수 있으므로, 이 실험만으로 원천 GPS 측정 주기를 역산할 수 없다.

## 구현 판단

첫 단계는 야탑·서현·정자·판교 주변에서 2~3개 노선을 선택하는 2D 지도다. 후보 확정 전 화면용 궤적은 **시연 데이터**로 표시한다. 키 연결 후에는 검증한 공식 노선 형상과 정류소를 사용하고, 정류소 상태를 기준으로 위치를 배치한다.

이동 애니메이션은 연속해서 받은 정류소 위치 사이의 노선상 거리를 따라 보간한다. 속도는 `노선상 이동거리 / 관측 시각 차이`로 얻은 **구간 평균 추정속도**다. 정보가 부족한 첫 관측, 동일 정류소, 회차, 비정상 점프에서는 속도를 알 수 없음으로 처리한다. 오래된 응답으로 계속 움직이거나 임의의 실시간 속도를 만들지 않는다. 매칭이 모호하면 정류소 수준의 표시로 돌아간다.

수신 시각, 마지막 상태 변경 시각, 화면 표시 시각을 분리한다. 응답이 늦거나 누락되면 움직임을 멈추고 지연 상태를 표시한다. 정류소 기준 추정과 원시 GPS 관측은 데이터 모델부터 구분한다.

## VWorld 3D 확장

V-world의 2026 개발 교육은 WebGL 3.0 로더(`map.vworld.kr/js/webglMapInit.js.do?version=3.0&apiKey=…`), `vw.Map`, 카메라 설정과 건물 레이어를 다룬다. 자체 인증키 발급도 안내한다. 따라서 3D 지도 확장은 가능하지만, 키 없이 동작 검증을 마쳤다고 볼 수는 없다. [V-world 2026 교육 자료](https://github.com/V-world/V-world_API_sample/blob/master/%EB%B8%8C%EC%9D%B4%EC%9B%94%EB%93%9C_%EA%B5%90%EC%9C%A1/2026%EB%85%84_%EB%B8%8C%EC%9D%B4%EC%9B%94%EB%93%9C_%EA%B5%90%EC%9C%A1/Readme.md)

이번 환경에서는 VWorld 개발센터가 시간초과 또는 502를 반환해 최신 도메인 제한·쿼터·이용 조건을 확인하지 못했다. 3D 전환 전에 발급 화면에서 localhost 및 실제 배포 도메인 허용 여부를 확인하고, 분당 건물 커버리지와 모바일 성능을 테스트한다. 버스 상태/보간 계산을 지도 엔진과 분리하면 2D에서 확인한 동작을 이후 VWorld에 연결할 수 있다.
